## Bug summary

### Bug #1 — `{{token}}` hover preview is dead in the URL bar (major)

See `docs/qa/2026-07-26-bugs.json` id 1. Root cause: the transparent `url-input` is
`absolute inset-0 z-[var(--z-raised)]`, layered **above** the syntax-highlight overlay that hosts
the hoverable `env-token` spans. Even though the spans carry `pointer-events-auto`, they never
receive the hover because the input fully covers the same box and isn't `pointer-events-none`.
Confirmed live via `document.elementFromPoint()` at the token's screen coordinates — it resolves
to `INPUT[data-testid=url-input]`, not the span, in the running dev-server app (not just under
Playwright). Regressed by commit `9af2269` ("Enhance tab functionality and add SSE support"),
which restructured the URL bar for long-URL scroll-sync and swapped which layer (input vs.
overlay) sits on top. `e2e/environments.spec.ts` already has a test for this exact behavior and it
fails deterministically (4/4 runs including an isolated `--repeat-each=3`).

Not a test bug — do not weaken/skip that assertion; it correctly locks the expected UX from
`docs/features/environments.md` ("Per-token hover preview under URL bar").

## Go / no-go

**Go, with one open major bug to track.**

- No blockers: core flows (request build/send, response viewer, collections, history/drafts,
  environments, import/export, settings, sidebar, content types) are all green across Vitest +
  Playwright + manual spot checks, including the mandatory long-URL / header-scroll / layout /
  Cmd+S edge cases.
- One **major**, non-blocking bug: `{{token}}` hover preview in the URL bar is completely
  non-functional (Bug #1). It's a UX regression on a documented, already-tested interaction, but
  it degrades gracefully — the resolved-URL preview line still renders under the URL bar whenever
  the interpolated URL differs from the raw one (`request-builder`'s `previewUrl` fallback), so
  users aren't blocked from understanding what will be sent; they just lose the per-token
  hover breakdown. Recommend fixing before next release but it does not need to block this pass.
- Docs updated: `docs/features/environments.md` and `docs/features/request-builder.md` (Open
  risks sections) now document the bug and its root cause so it doesn't get silently
  re-introduced or mistaken for flake.
